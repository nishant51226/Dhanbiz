# Reporting issues

When a checklist item fails or you hit an unexpected error, capture enough detail for your administrator or support team to reproduce it.

## Before you report

1. Check [Troubleshooting](./troubleshooting) for a known fix
2. Try a hard refresh or a different browser
3. Note whether other users see the same problem

## What to include

| Field | Example |
|-------|---------|
| **Date and time** | 23 Jun 2026, 14:30 BST |
| **Your role** | Admin / Manager / Portal user |
| **Page URL** | `/jobs/new` |
| **Steps to reproduce** | 1. Open Jobs → New job 2. Select customer 3. Upload PDF 4. Click Submit |
| **Expected result** | Job appears as Queued |
| **Actual result** | Red error: "Upload failed" |
| **Screenshot** | Attach full screen including error message |
| **Customer / job ID** | If applicable |

## Severity guide

| Level | When to use | Response expectation |
|-------|-------------|---------------------|
| **Critical** | Cannot sign in; data loss; all extractions failing | Immediate escalation |
| **High** | Core workflow blocked (onboarding, upload) | Same business day |
| **Medium** | Feature degraded but workaround exists | Next business day |
| **Low** | Cosmetic issue, typo, minor UI glitch | Scheduled fix |

## Who to contact

| Issue type | Contact |
|------------|---------|
| Access / passwords | Practice administrator (**Settings → Users**) |
| Customer data errors | Assigned account manager |
| Platform outage | IT lead or hosting provider |
| Billing / subscription plans | Practice owner |

## After reporting

- Do not delete failed jobs or uploaded files until investigated
- Administrator may ask you to repeat steps while screen-sharing
- Retest after a fix is deployed using the relevant [checklist](./checklists) item
